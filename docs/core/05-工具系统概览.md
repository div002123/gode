# 工具系统概览

## 模块作用

工具系统（tools/）是 Codex 中负责执行 AI 模型请求的各种操作的核心组件。它提供了一个可扩展的框架，用于注册、路由和执行不同类型的工具调用。

**在整体架构中的位置**：位于工具编排层，连接 AI 响应处理和实际的系统操作执行。

## 核心组件

### 1. ToolOrchestrator（工具编排器）
**文件**: `orchestrator.rs`

**职责**：
- 协调工具调用的整个生命周期
- 管理并行执行
- 处理依赖关系
- 集成沙箱和批准机制

**关键方法**：
- `execute_tools()` - 执行一批工具调用
- `handle_tool_result()` - 处理工具执行结果
- `check_approvals()` - 检查批准状态

### 2. ToolRegistry（工具注册表）
**文件**: `registry.rs`

**职责**：
- 注册可用工具
- 提供工具查找
- 管理工具元数据（名称、描述、参数模式）

**支持的工具类型**：
- 内置工具（Shell、文件操作等）
- MCP 工具（动态加载）
- 自定义工具

### 3. ToolRouter（工具路由器）
**文件**: `router.rs`

**职责**：
- 解析工具调用请求
- 路由到对应的处理器
- 验证参数
- 处理错误

### 4. ToolHandler（工具处理器）
**接口**: 定义在 `handlers/mod.rs`

**实现**：
```rust
pub trait ToolHandler {
    async fn execute(&self, params: Value, context: &ToolContext) -> Result<ToolResult>;
    fn name(&self) -> &str;
    fn schema(&self) -> ToolSchema;
}
```

**内置处理器**：

#### Shell 工具
- **文件**: `handlers/shell.rs`
- **功能**: 执行 Shell 命令
- **特性**: 沙箱检查、批准流程、输出捕获

#### 文件操作工具
- **read_file.rs**: 读取文件内容
- **grep_files.rs**: 在文件中搜索
- **list_dir.rs**: 列出目录内容
- **apply_patch.rs**: 应用代码补丁

#### MCP 工具
- **mcp.rs**: 调用 MCP 服务器提供的工具
- **mcp_resource.rs**: 读取 MCP 资源

#### 统一执行
- **unified_exec.rs**: 统一的命令执行接口

### 5. 工具运行时（ToolRuntime）
**目录**: `runtimes/`

**职责**：
- 提供工具执行的底层实现
- 管理进程生命周期
- 处理 I/O 流
- 实现超时和取消

## 工具执行流程

### 完整流程
```
AI 请求工具调用
  ↓
parse_turn_item() 解析为 ToolCall
  ↓
ToolOrchestrator.execute_tools()
  ↓
分组：并行执行 vs 顺序执行
  ↓
ToolRouter.route(tool_name)
  ↓
查找 ToolHandler
  ↓
检查沙箱策略
  ↓ 需要批准
ApprovalStore.request_approval()
  ↓
发出 ExecApprovalRequest 事件
  ↓
等待用户响应
  ↓ 批准
ToolHandler.execute(params, context)
  ↓
ToolRuntime 执行实际操作
  ↓
捕获输出和错误
  ↓
返回 ToolResult
  ↓
格式化为 FunctionCallOutput
  ↓
添加到上下文
```

### 并行执行流程
```
多个工具调用
  ↓
分析依赖关系
  ↓
分组：
  - 独立工具 → 并行
  - 依赖工具 → 顺序
  ↓
创建 FuturesUnordered
  ↓
并发执行所有独立工具
  ↓
等待所有完成
  ↓
收集结果
```

## 沙箱和安全

### 沙箱策略
**文件**: `sandboxing.rs`

**策略级别**：
- `Disabled`: 无沙箱
- `Ask`: 危险操作需要批准
- `Strict`: 严格限制

### 命令安全检查
**文件**: `command_safety/`

**功能**：
- 检测危险命令（rm -rf、dd、格式化等）
- 白名单安全命令
- 平台特定规则

### 批准流程
**组件**: `ApprovalStore`

**流程**：
1. 工具请求批准
2. 生成批准 ID
3. 发送批准请求事件
4. 阻塞等待用户响应
5. 根据响应继续或取消

## 工具规范（ToolSpec）
**文件**: `spec.rs`

**定义**：
```rust
pub struct ToolSpec {
    pub name: String,
    pub description: String,
    pub input_schema: Value,  // JSON Schema
}
```

**用途**：
- 告诉 AI 可用的工具
- 定义参数格式
- 生成工具文档

**工具配置**：
```rust
pub struct ToolsConfig {
    pub tools: Vec<ToolSpec>,
    pub parallel_tool_calls: bool,
}
```

## 执行上下文（ToolContext）
**文件**: `context.rs`

**包含**：
- 工作目录 (cwd)
- 环境变量
- 配置引用
- MCP 连接管理器
- UnifiedExec 会话管理器
- 取消令牌
- 差异追踪器

**作用**：为工具执行提供必要的环境和资源。

## 工具事件（ToolEvent）
**文件**: `events.rs`

**事件类型**：
- `ToolStarted`: 工具开始执行
- `ToolProgress`: 执行进度
- `ToolCompleted`: 执行完成
- `ToolFailed`: 执行失败
- `ApprovalRequested`: 请求批准
- `ApprovalReceived`: 收到批准响应

## 并行执行（Parallel）
**文件**: `parallel.rs`

**特性**：
- 分析工具依赖关系
- 创建执行计划
- 使用 `FuturesUnordered` 并发执行
- 处理部分失败

**优化**：
- 减少总执行时间
- 提高吞吐量
- 保证依赖顺序

## 扩展工具系统

### 添加新工具
1. 在 `handlers/` 中创建新处理器
2. 实现 `ToolHandler` trait
3. 在 `ToolRegistry` 中注册
4. 定义工具规范（名称、描述、参数模式）

### 示例：
```rust
pub struct MyToolHandler;

impl ToolHandler for MyToolHandler {
    async fn execute(&self, params: Value, context: &ToolContext) -> Result<ToolResult> {
        // 实现工具逻辑
        Ok(ToolResult::success("Done"))
    }

    fn name(&self) -> &str {
        "my_tool"
    }

    fn schema(&self) -> ToolSchema {
        ToolSchema {
            name: "my_tool".into(),
            description: "My custom tool".into(),
            input_schema: json!({
                "type": "object",
                "properties": {
                    "param1": {"type": "string"}
                }
            }),
        }
    }
}
```

## 性能优化

- **并行执行**: 独立工具同时运行
- **流式输出**: 大输出增量传输
- **超时控制**: 防止工具挂起
- **资源池**: 复用 Shell 会话、MCP 连接

## 错误处理

- **工具不存在**: 返回 ToolNotFound 错误
- **参数无效**: 返回 InvalidParams 错误
- **执行失败**: 返回 ExecutionFailed 错误
- **超时**: 返回 Timeout 错误
- **用户拒绝**: 返回 ApprovalDenied 错误

所有错误都会被格式化为 `FunctionCallOutput` 返回给 AI，让 AI 决定如何处理。
